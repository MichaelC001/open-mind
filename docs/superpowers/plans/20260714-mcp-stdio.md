# MCP Stdio Transport Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `openmind mcp` serves the full MCP tool/resource/prompt registry over stdio for co-located self-hosts (`claude mcp add openmind -- openmind mcp`), single-user only.

**Architecture:** Extract the `*mcp.Server` construction out of `internal/mcp.NewHandler` into `NewServer` (HTTP handler becomes a thin wrapper); export a Backend constructor from `internal/api` that builds the `mcpBackend` adapter without the HTTP router; add an `mcp` subcommand to `cmd/openmind` that refuses Clerk mode, uses the fixed dev user, and calls the SDK's `server.Run(ctx, &mcp.StdioTransport{})`.

**Tech Stack:** Go, `github.com/modelcontextprotocol/go-sdk` v1.6.1 (`StdioTransport`, `NewInMemoryTransports` for tests). No new dependencies.

**Spec:** `docs/superpowers/specs/20260714-mcp-stdio-design.md`

## Global Constraints

- Single-user only: in Clerk mode (`AUTH_MODE=clerk`) the subcommand exits non-zero with exactly: `stdio transport is single-user only — use the HTTP transport at /mcp with a device key`.
- All logging to stderr (stdout is the JSON-RPC channel). slog's default handler already writes to stderr — no slog call may be redirected to stdout.
- The stdio process embeds an insert-only River client (no workers); enrichment of stdio saves needs a separate `openmind work`/`all` process, documented.
- No new dependencies; no REST contract change; behaviour of the HTTP `/mcp` path unchanged.
- Go commands run from `apps/api`; use `env -u GOROOT /opt/homebrew/bin/go` if go.work versioning bites.
- No banner-style comment blocks.

```go
// NewServer builds the MCP server with the full registry — tools, the item
// resource template, and prompts. Transport-agnostic: the HTTP layer wraps it
// in a Streamable HTTP handler and the stdio command runs it directly.
func NewServer(b Backend, uidFor func(context.Context) uuid.UUID) *mcp.Server {
	server := mcp.NewServer(&mcp.Implementation{Name: "openmind", Version: "0.1.0"}, nil)
	registerTools(server, b, uidFor)
	registerResources(server, b, uidFor)
	return server
}

// NewHandler wraps NewServer's registry in a Streamable HTTP handler ready to
// mount. uidFor resolves the caller from the per-request context.
func NewHandler(b Backend, uidFor func(context.Context) uuid.UUID) http.Handler {
	server := NewServer(b, uidFor)
	return mcp.NewStreamableHTTPHandler(func(*http.Request) *mcp.Server { return server }, nil)
}
```

In `apps/api/internal/api/mcp.go`, add:

```go
// NewMCPBackend builds the MCP Backend adapter without the HTTP router, for
// transports that never serve HTTP (the stdio command). It wraps a minimal
// *Server carrying only the dependencies the MCP tools reach: the store,
// an insert-only River client (save_item enqueues enrichment), and the AI
// provider (search query parsing). Asset/feed/kindle handlers are HTTP-only
// and never reached through the Backend interface.
func NewMCPBackend(s *store.Store, riverClient *river.Client[pgx.Tx], provider ai.Provider) appmcp.Backend {
	return mcpBackend{&Server{store: s, riverClient: riverClient, provider: provider}}
}
```

```go
// errStdioSingleUser is returned when `openmind mcp` starts in Clerk
// multi-user mode: stdio has no per-request credential, so it can only ever
// act as the single auto-provisioned account.
var errStdioSingleUser = errors.New("stdio transport is single-user only — use the HTTP transport at /mcp with a device key")

// checkStdioAuthMode refuses the stdio transport outside single-user token
// mode. It only inspects AUTH_MODE — a bad mode string fails later in
// authConfigFromEnv as usual.
func checkStdioAuthMode() error {
	if os.Getenv("AUTH_MODE") == api.AuthModeClerk {
		return errStdioSingleUser
	}
	return nil
}
```

Add the runner beside `serveHTTP`:

```go
// serveStdio serves the MCP registry over stdin/stdout as the single dev
// user, until the client closes the pipe or the process is signalled. All
// logging must stay on stderr (slog's default) — stdout is the JSON-RPC
// channel. The embedded River client is insert-only: saves enqueue
// enrichment, but a separate `openmind work` or `all` process must be
// running to process the queue.
func serveStdio(ctx context.Context, s *store.Store, client *riverClient, provider ai.Provider) error {
	ctx, stop := signal.NotifyContext(ctx, os.Interrupt, syscall.SIGTERM)
	defer stop()

	backend := api.NewMCPBackend(s, client, provider)
	server := appmcp.NewServer(backend, func(context.Context) uuid.UUID { return api.DevUserID })
	slog.Info("mcp stdio transport serving", "user", api.DevUserID)
	if err := server.Run(ctx, &sdkmcp.StdioTransport{}); err != nil && !errors.Is(err, context.Canceled) {
		return fmt.Errorf("mcp stdio: %w", err)
	}
	return nil
}
```

Note the subcommand runs AFTER the shared setup in `run()` (pool, migrate, EnsureUser, provider, pipeline) — it needs no changes there; `EnsureUser(ctx, api.DevUserID)` already guarantees the account exists.

### Local (stdio)

If your MCP client runs on the same machine as the Openmind binary (or you can `docker compose exec` into it), you can skip HTTP entirely:

claude mcp add openmind -- openmind mcp
# or against the compose stack:
claude mcp add openmind -- docker compose exec -T api openmind mcp

It reads the same `DATABASE_URL` as the API.
